# ui-ad-reporter

A single-screen mobile PWA for the "I just saw an ad" reporting workflow. One
view is a single button that reports an ad just seen on the LAN; the other
lists reports the backend hasn't resolved yet.

Designed to be installed via "Add to Home Screen" and used from a phone.

## Views

- `/` — one button, "I just saw an ad." Tapping it fires the `reportAd`
  mutation and shows a brief confirmation. No further client-side state is
  tracked.
- `/unresolved` — lists every report from the `unresolvedReports` query,
  newest first: timestamp (converted from UTC to America/Chicago for
  display) and client IP. Read-only — there's no manual-resolve action in
  this UI; resolving is handled by the `ad-reporter-investigate` Claude
  Skill or left for a human to triage via the Discord channels it posts to.

## Stack

- React 19 + TypeScript + Vite
- Apollo Client, with typed hooks generated by GraphQL Code Generator from
  the vendored [`schema.graphql`](./schema.graphql)
- `react-router-dom` for the two client-side routes
- `vite-plugin-pwa` for an installable app shell only — there is deliberately
  **no offline caching of API responses**. A stale "unresolved reports" list
  would be actively misleading, so the service worker is configured
  `NetworkOnly` for the GraphQL origin.
- lucide-react icons
- Vitest + React Testing Library + MSW for component tests, Playwright for E2E
  (both mock the GraphQL endpoint at the network layer — there's no live
  backend reachable in CI or from a sandboxed dev environment)
- ESLint (flat config) + Prettier

## Running locally

Requires Node 22 (on NixOS: `nix shell nixpkgs#nodejs_22 --command <cmd>`).

```bash
npm install
npm run dev
```

By default the app talks to the live router at `https://graphql.morrisons.site/`.
To point it elsewhere (e.g. a local mock), set `VITE_GRAPHQL_ENDPOINT` in a
`.env.local` file.

### Tests

```bash
npm run test          # unit/component tests (Vitest + RTL + MSW)
npm run test:e2e      # end-to-end tests (Playwright, GraphQL mocked at the network layer)
npm run test:e2e:smoke # runs only the @smoke-tagged test, unmocked, against the real deployed app
```

`test:e2e:smoke` is what CI runs post-deploy — it's the one test in
`e2e/ad-reporter.spec.ts` that never fires the `reportAd` mutation, so it's
safe to run against the real, live app without creating a real report row.
Every other e2e test mocks the GraphQL endpoint.

Playwright needs a Chromium build once:

```bash
npx playwright install --with-deps chromium
```

On NixOS, `--with-deps` fails (no `apt`/passwordless `sudo` for the OS-level
libraries). Use the NixOS-packaged, pre-patched browsers instead and skip the
download:

```bash
PLAYWRIGHT_BROWSERS_PATH=$(nix eval --raw nixpkgs#playwright-driver.browsers) \
  nix shell nixpkgs#nodejs_22 nixpkgs#playwright-driver.browsers --command npx playwright test
```

(`@playwright/test` is pinned in `package.json` to match the browser build
version shipped by `nixpkgs#playwright-driver` at the time this was set up —
bump both together if you upgrade.)

`vite`, `vitest`, `@vitest/coverage-v8`, `@vitejs/plugin-react`, and `jsdom`
are pinned to exact versions, and `rolldown` (vite's bundler dependency) is
pinned via `overrides`, matching the specific combination confirmed working
in this homelab (`ui-hdmi-switch`'s own lockfile). A newer `rolldown` native
build (`@rolldown/binding-linux-x64-gnu` 1.2.18, vs. the pinned 1.2.4)
crashes with `SIGILL` on at least one dev environment used for this repo —
likely a native build assuming a newer CPU instruction set than every
machine running this code is guaranteed to have. Re-test on real hardware
before loosening any of these pins.

### Other checks

```bash
npm run lint          # ESLint
npm run format:check  # Prettier
npm run build          # tsc + production build
npm run codegen        # regenerate src/graphql/generated.tsx from schema.graphql + src/**/*.graphql
```

## GraphQL schema

`schema.graphql` is a vendored copy of the operational part of the live,
federated schema at `https://graphql.morrisons.site/` (the real federated
schema also carries Apollo Federation `_service`/`join` directives, which are
irrelevant to this client). CI has no network access to introspect the live
endpoint, so this file is the source of truth for codegen — keep it in sync by
hand if the `graph-ad-reporter` backend schema changes.

```
├── build    — npm run build
├── release  — static dist/ served via nginx:alpine; bakes a COMMIT_SHA build

└── test     — runs the unit test suite
```

This repo is source + CI only — no Kubernetes manifests here. Deployment
manifests live in a separate `k8s-ad-reporter` repo.
